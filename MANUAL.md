# Manual

A guide to maintaining this site.

Two assumptions in this doc:

- repo is hosted on github
- cloudflare pages is used for hosting

## Overview

This is a static site generated by [Hugo](https://gohugo.io/) from Markdown files in `content/`, with HTML templates in `layouts/` and styles in `assets/css/`.

Cloudflare Pages watches the `main` branch on GitHub; every push to `main` triggers a rebuild and redeploys in about a minute.

You don't need Hugo installed locally for content changes — Cloudflare builds it. Hugo is only needed if you want to preview changes before pushing (see Appendix A).

The main reason we use hugo is for compositional reasons. Without it you would have to write the nav component on every html file and edit it on every html file when you make a change. With hugo we can configure it once and re-use it across the site.

### Repo layout

```
content/                # Markdown content — the main thing you edit
  _index.md               # Homepage body
  about.md
  now.md
  cv.md
  links.md
  blog/                   # One file per blog post
    _index.md               # Intro text for the blog index page
    *.md                    # Individual entries
  projects/
    _index.md
    *.md
layouts/                # HTML templates — touch to change structure
  _default/
    baseof.html             # Outer page shell (head, body, nav, footer)
    single.html             # Individual content pages
    list.html               # Index pages (blog, projects)
  index.html              # Homepage layout
  partials/
    nav.html
    footer.html
assets/css/main.css     # All site styling
static/                 # Files served as-is (images, downloads, etc.)
hugo.toml               # Site config: title, tagline, nav menu
```

The Hugo version used to build the site is pinned via the `HUGO_VERSION` environment variable in Cloudflare's project settings.

## Publish loop

```
edit → commit → push → ~1 min → live
```

There's no staging environment. Pushing to `main` deploys to production. If you push something broken, fix it and push again — rollback is also a push (see Troubleshooting).

## Common tasks

### Add a blog post

Create `content/blog/<slug>.md`.

Each content markdown file starts with a frontmatter block.

Frontmatter is the YAML between `---` markers that sets page metadata like title and date:

```markdown
---
title: "My post title"
date: 2026-06-01
designation: "LOG-002"
---

Post body in markdown.
```

The filename becomes the URL slug, so `content/blog/my-post.md` lives at `/blog/my-post/`. Stick to lowercase and hyphens.

The blog index page lists every file in `content/blog/`, newest first by `date`.

### Add a project entry

Same as a blog post, but under `content/projects/`:

```markdown
---
title: "Project name"
date: 2026-06-01
designation: "OP-002"
---

Description.
```

### Update the Now page

Edit `content/now.md`. Change the `updated:` date in the frontmatter when you change the content — it's rendered as a `LAST UPDATED` line on the page.

```markdown
---
title: "Now"
designation: "CURRENT STATUS"
updated: "2026-06-15"
---
```

### Embed an image

Put the source image in `assets/images/` (create the folder if needed). Use the `img` shortcode in markdown.

A shortcode is Hugo's syntax for embedding custom components; you call it with `{{< name ... >}}` and Hugo expands it at build time using the matching template in `layouts/shortcodes/`:

```markdown
{{< img src="screenshot.png" alt="Description" >}}
```

At build time Hugo converts the image to WebP, fingerprints the URL, and resizes anything wider than 1400px down to fit. JPEG, PNG, GIF, TIFF, BMP, and WebP sources all work; WebP sources at or below the width cap pass through untouched. The shortcode also sets `width`, `height`, and `loading="lazy"` on the `<img>` tag.

Optional `width` parameter to override the 1400px cap (in pixels):

```markdown
{{< img src="thumb.png" alt="..." width="600" >}}
```

For non-image static files (PDFs, downloads, etc.), drop them in `static/` and link with a normal markdown link. Hugo serves `static/` at the site root, so `static/cv.pdf` lives at `/cv.pdf`.

### Change the site title or tagline

In `hugo.toml`:

```toml
title = 'RADIGAN'

[params]
  tagline = "INDUSTRIAL AUTOMATION // PERSONAL TERMINAL"
```

`title` appears in the header and the browser tab. `tagline` appears under the title on the homepage only.

### Add or remove a nav item

Each nav item is a `[[menu.main]]` block in `hugo.toml`:

```toml
[[menu.main]]
  name = "ABOUT"
  url = "/about/"
  weight = 10
```

`weight` controls display order — lower numbers appear first. The actual values are arbitrary (10, 20, 30... or 1, 2, 3... — doesn't matter), only their relative order counts. Add a block to add an item, delete a block to remove one.

### Delete a page entirely

1. Delete the content file (e.g. `content/cv.md`)
2. Delete its `[[menu.main]]` block from `hugo.toml`

### Add a new top-level section (e.g. `/reading/`)

1. Create `content/reading/_index.md` with a `title` and optional `designation`
2. Add entries as `content/reading/<slug>.md`
3. Add a nav item in `hugo.toml`:
   ```toml
   [[menu.main]]
     name = "READING"
     url = "/reading/"
     weight = 70
   ```

Sections automatically use `layouts/_default/list.html` for the index and `layouts/_default/single.html` for entries. No template work needed.

## Frontmatter reference

The `---` block at the top of each markdown file. Hugo recognises some field names as built-ins with hard-coded behaviour (e.g. `title`, `date`, `draft`, `slug`); anything else is treated as custom and accessed in templates via `.Params.<name>`. Fields used by this site:

| Field         | Required           | Source | Purpose                                                      |
| ------------- | ------------------ | ------ | ------------------------------------------------------------ |
| `title`       | yes                | Hugo   | Page title; used in `<title>` and `<h1>`                     |
| `date`        | blog/projects only | Hugo   | Sort order on index pages; rendered as `FILED` on entries    |
| `designation` | no                 | custom | The `[ ... ]` label above the title. Defaults to `[ TITLE ]` |
| `updated`     | no                 | custom | Rendered as `LAST UPDATED` (used on the Now page)            |

Hugo supports other built-in fields (`draft`, `tags`, `aliases`, `lastmod`, etc.) — this site doesn't use them, but they'll work if you add them. Full list: <https://gohugo.io/content-management/front-matter/>.

## Layouts and CSS

You don't need to touch these for content changes. Touch them to change how the site looks or is structured.

| File                           | What it controls                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `layouts/_default/baseof.html` | Outer HTML shell — `<head>`, body wrapper, includes nav and footer                                                   |
| `layouts/_default/single.html` | Layout for individual content pages                                                                                  |
| `layouts/_default/list.html`   | Layout for index pages (blog, projects, etc.)                                                                        |
| `layouts/index.html`           | Homepage layout                                                                                                      |
| `layouts/partials/nav.html`    | Header and nav, included from `baseof.html`                                                                          |
| `layouts/partials/footer.html` | Footer, included from `baseof.html`                                                                                  |
| `layouts/shortcodes/img.html`  | The `{{< img >}}` shortcode (see Embed an image). Edit to tweak the image pipeline (e.g. change quality, max width). |
| `assets/css/main.css`          | All styling. CSS variables at the top define colours, rules, fonts.                                                  |

Hugo's templating syntax is `{{ ... }}`. The full reference is at <https://gohugo.io/templates/introduction/>.

If you change the CSS variables at the top of `main.css` (`--bg`, `--fg`, `--accent`, etc.), the change propagates everywhere.

## Troubleshooting

**Push succeeded but the site didn't update.**

Wait a minute, then check Cloudflare's deployment log: dash.cloudflare.com → Workers & Pages → `radigan-site` → Deployments. Failed builds show the error in the log — usually a typo in `hugo.toml` or invalid frontmatter (often a missing quote or unescaped colon).

**Build fails with a Hugo version error.**

Hugo's version is pinned via the `HUGO_VERSION` env var in Cloudflare's project settings. Bump it there if a new feature requires a newer Hugo.

**You broke something and want to roll back.**

Just revert and push via git, Cloudflare rebuilds from the reverted state.

## Appendix A: Local preview (optional)

If you want to preview changes before pushing:

1. Install Hugo (extended edition): <https://gohugo.io/installation/>
2. From the repo root, run `hugo server`
3. Open <http://localhost:1313> (assuming the default port is still 1313)

The server live-reloads on file changes. Ctrl-C stops.

This is entirely optional because Cloudflare's build catches most issues and the push-and-wait loop is fast enough that local preview isn't strictly necessary.

One reason to consider this is that on the free tier of cloudflare you're limited to 500 builds permonth, so if you were rapidly trying out different changes then a local preview would stop you blowing through your build budget.
